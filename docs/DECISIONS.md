## ADR-001 · 精确 ROM 适配，而不是通用内存地址

**决定：保留。** PyBoy 负责 GB 模拟；只接受 Red Star 文件哈希 `e2d564a5172d38e44b4f4b8f7d9db92f644cf5e9`。原版 Red 与 GBA FireRed 不共享同一适配器。

**原因：** 文件扩展名和“能开机”只证明很有限的兼容性，不证明玩家坐标、队伍、背包等字段地址正确。历史源码重建与用户 ROM 不逐字节一致，所以地址来源与实机验证分开记录。

**代价：** 不会静默支持其他语言、版本或改版；更换 ROM 必须重新验证。配置与先验留在 Git，原用户上传文件按 ADR-008 恢复；新增其他游戏仍需单独适配。

## ADR-002 · 设备动作固定，剧情策略不应由按键目录假装产生

**决定：保留九个物理输入。** 每个执行按键仍由 Jev 返回并校验；代码不执行模型生成的代码、RAM 写入或固定剧情按键宏。

**原因：** 有限按键是设备接口，不是智能来源。早期“只给状态和按键”的方案会原地循环，长期目标、记忆和界面辨识必须由 harness 明确提供。

**权衡：** 当导航已经给出确定路径时，再让 Jev 每格重选可能冗余。当前为保持逐键模式没有隐藏自动导航；以后引入技能执行器，应另记 ADR 并标出哪些动作由程序执行，不能沿用“全部模型逐键完成”的解释。

## ADR-003 · 保留记忆与路径工具，但把固定主线降为参考/对照

**早期方案：** `campaign_knowledge.py` 的主线规则选择目标，`CampaignPlanner` 计算路径，Jev 再选按键。这能推进已知任务，但新剧情障碍出现时可能持续给错误建议。

**当前决定：已替代默认双模型策略。** 在 `deepseek` 模式中，CampaignPlanner 管理世界记忆、计划、导航与验收；固定故事目录只作为注明来源的知识。`local` 显式保留旧方案，用于对照而非伪装成 DeepSeek。

**仍保留：** 区域路由与条件伤害计算是算法工具，不必让语言模型重复计算。源码先验不能推翻真实观察，也不能证明故事已经完成。

## ADR-004 · 从“卡住顾问”到“有生命周期的 System Two”

**前案 `5bd578d`：** 无新坐标/循环后才调用 DeepSeek；已有计划阻止再次规划，主要靠 TTL 结束。完成字段与验证器未接通，现场对白和对象信息也不足。

**现案 `6c0c35c`：** 启动或没有有效计划时先规划；结束分为完成、失败、失效、到期，治疗期间暂停。完整计划结果进入持久记忆，下一次请求包含失败原因、对白、对象和出口。

**验收边界：** `target_reached` 不等于对话或剧情完成；`battle_finished` 不等于获胜；终局仍需经过独立验证的游戏证据。只增加模型或提示词不能代替这些合同。

## ADR-005 · 目标引用、单一当前意图与受控降级

**决定：保留。** 规划模型只返回 `target_ref`，从本次目标目录解析坐标。合同拒绝不存在的引用、非法参数、代码与按键序列。未知状态不满足成功条件。

紧急治疗暂停模型计划与 TTL；恢复后重新评估。不把“继续过洞穴”和“回中心治疗”同时写成当前命令。`deepseek` 模式缺服务就暂停，`auto` 的规则回退必须明确记录，`local` 是用户显式选项。

**原因：** 格式正确的 JSON 不一定可执行；把资源配置存起来不等于所有模块已消费它。模型配置、请求、接受计划、实际动作和效果必须分别可观察。

## ADR-006 · 结果展示与控制解耦，活动不等于进展

**决定：保留。** 游戏控制只有一个进程；HLS 来自实际 RGB 帧，SSE 来自实际事件。网页只读、默认本机监听，不能产生第二套输入。

活动指标与主线验收分离：旧路移动、HP/PP 变化可以证明系统仍工作，但不能证明更接近通关。停滞恢复保留已探索地形，不通过清空关键证据反复尝试同一计划。

**已知限制：** HLS 只保留短窗口，事件与画面有缓冲偏差；长周期补给循环、后期机关及月见山策略效果仍需要对应会话的实测，不能从局部测试外推。

## ADR-007 · Git 保存知识，运行目录保存证据

**历史决定：部分由 ADR-008 纠正。** `71a9cd8` 当时移除 `pokemon/evidence/`、`pokemon/archive/`、`pokemon/results/`、一次性维护脚本及孤立的 `test_*_live.py` 探针。取消 Actions 把回放自动提交进 `main` 的权限和步骤。ROM、密钥、存档、日志、回放和视频受 `.gitignore` 排除。

**保留范围：** 核心运行代码、必需配置/地图/招式数据、其重建工具、第三方许可证、纯核心回归测试源码，以及三份维护文档。`artifacts.py` 是状态读写逻辑，`render_results.py`/`replay.html` 是离线查看器源码，不能与生成物混淆。

原 101 步游戏记录夹具替换为明确标记的合成活动序列回归；新的测试不再依赖被删除的实测目录。历史记录仍可通过提交找到，不重写历史，也不宣称原 ROM 已从历史彻底移除。

**代价与迁移：** 自动 CI 不再含游戏/付费模型运行。真实验证在本地配置 ROM/密钥后进行。旧用户先复制 ROM 到 `roms/` 再拉取；运行时可显式指定该路径，或复制回已忽略的原路径。当前清理不是性能/策略修复，也没有新增通关结论。

## ADR-008 · 恢复误删资产；按职责迁移，不用删除代替整理

**日期：2026-09-23；状态：采用。** 用户指出上一轮把 ROM 和可复用的实机回归误当临时产物，且测试和 System Two 提示仍散落。这是清理范围判断错误，不是用户要求删除资产。

**决定：** 从清理前历史恢复两份原上传 ROM 到 `roms/`，保留原 blob 身份；恢复四个实机/模型验证脚本到 `tests/integration/`。不恢复已明确要求移出的 evidence/archive/results 大量生成报告，也不重新启用自动把回放提交到 Git 的 publisher。

**目录合同：** 全部测试集中 `tests/python`、`tests/web`、`tests/integration`；运行代码不放 `test_*.py`。两类固定提示集中 `prompts/system1`、`prompts/system2`；`planning.py` 只负责状态构造、调用和校验。必需静态数据集中 `pokemon/data`，公共路径解析在 `pokemon/paths.py`。

**兼容：** 继续支持根目录旧 ROM 和显式 `--rom`，没有旧文件时自动读恢复的 `roms` 副本。`npm start`、`--resume`、用户 `.env`、运行目录和 checkpoint/记忆格式不变。只读前端及角色分工不改变；没有额外的模型调用或控制宏。

**验证合同：** 固定提示抽取前后 SHA-256 相同；Python 与前端测试覆盖路径、导入、启动、恢复和目录边界；CI 单独运行恢复的真实 ROM 脚本回归，不消耗模型额度。私有存档缺失明确 skip，模型实测需 `--allow-model-calls`，不作为默认单测。

**今后：** 清理只能默认排除生成报告与缓存；用户上传资产、可复用测试、必需数据和许可文件不得以“精简”为理由删除。重构先移动、修正引用并验证，再记录实际行为是否有变化。

## ADR-009 · 观察边界与策略权分离（2026-09-23）

**状态：采用；替代 ADR-003/005 中默认源码参考和自动治疗仲裁。** 用户指出“代码只提供建议”仍可能提前给答案，RAM 字段准确也不等于角色已观察到。前案虽然接入 DeepSeek，仍在状态清洗中调用招式排名、按血量覆盖目标，并把固定剧情目标及全图路径装进候选。

**考虑方案：** 只从提示词删除建议不够，因为候选、默认值、旧存档也会泄漏；删除所有算法和状态也不合理，会丢失必要界面信息及观察经验。采用独立的 observed 默认链，旧方案显式 assisted 对照而非整文件删除。

**决定：** `perception → Experience → DeepSeek → PlanManager → Jev → 执行`。过滤不可观察剧情和敌方内部属性；保留自身状态、当前文本/菜单/视野与通用招式描述。经验记录已看到/执行的结果，模型笔记带证据引用但不升格成事实。只对模型已选目标提供观察地图上的路径几何。无自动治疗/招式选择/默认逃跑；风险中断需由模型显式声明。Jev 新增独立计划适用性问题，要求 replan 时不执行并行按键。

**迁移：** 默认 `--knowledge-mode observed`；旧实测和策略测试明确使用 assisted。旧 sidecar 仅迁移标明来源的实际观察，拒绝旧策略计划；原文件不覆盖。ROM、目录布局、web、环境变量和游戏状态格式不变，计划及经验使用新的版本标记。

**验证：** 默认路径有隐藏字段反事实、无自动低血量接管、无最佳招式、笔记证据校验、记忆往返、完成后重规划、计划审查丢弃按键等测试。旧策略测试保留为明确的 assisted 对照。真实 ROM integration 验证过滤与序列化，模拟服务测试不声称真实模型已玩过。实际 CI/模型试跑结论以本次 PR 的运行记录为准，不在 Git 存原始日志。

**代价/限制：** 少了全图和攻略可能降低短期进度，不能承诺更快通关。结构化坐标、局部传送点和自身状态仍比像素输入丰富；敌方血条为量化估计，模型也有预训练知识，所以不称严格无先验基准。高频 replan 会消耗规划预算；路径未知和地图源版本不匹配仍需要更多观察，不能靠“让模型想”补出缺失数据。

## ADR-010 · 失败属于一次尝试，不应成为永久世界知识（2026-09-23）

**状态：采用；在 `18e92c1` 的 observed 默认链上增量修正。** 不重复引入另一套控制器，不覆盖已更新的观察过滤和经验记忆。保留旧分支的想法但不合入其过时实现。

**问题一：** `same_position_steps` 或 `steps_since_new_tile` 增长就结束计划，会误伤正常对白、战斗和经过已知道路的返程。旧计划遗留的循环信息也不能证明新计划执行失败。

**处理：** `plan_review.py` 只检查创建计划之后、连续并与当前动作计数对齐的实际 effects。行动后的观察持续不变，或同一观察条件下在很小的空间循环，才生成可检查的停滞诊断。文本、战斗、队伍、背包或同一位置的新观察变化会打断循环证据。记录不足保持未知；80 动作预算与 64 条经验保留上限分别注明，不能声称持有不存在的记录。超时、失败和完成仍然分开。

**问题二：** 对所有失败目标永久移除 `target_ref`，会把一次按键/交互失败变成“此地永远不可达”，NPC 移动或剧情变化后也无法再评估。

**处理：** 失败记录增加 `failure_observation_id`。只在相同的行动相关观察下暂缓同一失败目标；观察变化后重新提供该目标，但保留失败原因、步骤与来源。无上下文的旧记录不能变成永久禁令。`target_failures` 同时进入两个模型的输入，说明是失败尝试，不是不可达证明；模型决定是否重试以及怎样改变策略。

**权限边界：** 这些检查不选替代目标、不生成按键、不自动回城/逃跑、不从源码补地图。Jev 仍可主动请求 System Two，计划风险条件仍必须由模型声明。九个设备输入不因这些诊断被删减。

**兼容：** 延续现有 `observed_v1` 存档；只是为 plan_history 增加可选字段。ROM、运行入口、前端和存档路径不变，旧 assisted 对照未删除。全部新增测试位于 `tests/python/test_plan_review.py`，没有提交运行产物。

**验证与已知边界：** 覆盖计划内窗口、旧循环、观察缺口、长对白、战斗变化、已知路径移动、真实无效果、小范围循环、新对象出现、同/异上下文目标重试、两模型输入和存档往返。合成测试验证控制逻辑，不证明月见山或通关能力；实机与付费模型结果分别记录在 PR/Actions，而不是把单测通过当作游戏成绩。长期大范围循环仍需模型利用跨计划记忆分析，当前不会凭无新坐标独断其失败。

## 如何维护下一次决策

追加 ADR，不覆盖旧结论。至少写清：日期和提交/PR、触发问题、考虑过的方案、采用的分工、兼容性/迁移影响、实际验证范围、已知代价。实现前的方案标记“提议”，不能写成已经完成。

能指导维护的故障结论写进问题手册；原始 JSON、截图和长日志留在本地或受控附件，只保留必要的来源标识。不要为了更新“最新运行状态”自动改架构文档。
